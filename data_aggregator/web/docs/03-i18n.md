# 03 · i18n — EN · नेपाली · हिन्दी

```
  /                ──proxy.ts──▶ 302 /{lang}        lang = first supported primary subtag in Accept-Language, else en
  /{lang}/…        ──────────▶ app/[lang]/…        <html lang="ne-NP">, fonts, copy
                                   │
                                   ├─ t(lang, key, vars)      messages/{lang}.json → messages/en.json → key
                                   ├─ localised(row, "name")  places.name_ne → name_en
                                   └─ tEnum(lang, "access", v) access.helicopter_only → raw value
```

## 1. Routes

- Every page lives under `/[lang]` with `generateStaticParams` for `en`, `ne`, `hi` (`lib/i18n.ts` → `LANGS`).
- `proxy.ts` (Next 16's renamed middleware) redirects unprefixed paths. It honours q-ordered Accept-Language and
  matches primary subtags, so `ne-NP` → `/ne`, `hi-IN` → `/hi`. Files and `/api/*` are excluded by the matcher.
- `LangToggle` keeps the rest of the path and the query string when switching, so shared links keep their language.
- `AuthBootstrap` upserts `users.lang` on every page load, so the pipeline knows which language to answer in.

## 2. Messages

- `messages/en.json` is the complete copy: every string on every page, including chips, errors and empty states.
- `messages/ne.json` and `messages/hi.json` have **identical keys and order**. `scripts/i18n-check.mjs`
  (`npm run i18n:check`) fails on missing/extra keys, empty values, placeholder mismatches and Devanagari digits;
  `tests/messages.test.ts` runs the same checks under Vitest.
- Placeholders are `{name}` and are interpolated by `t()`; keep them verbatim in translations.
- Latin-only keys (set in Press Start 2P): `live.right_now`, `report.how_label`, `report.listening`,
  `me.privacy_label`, `place.corridor_label`, `about.agencies_label`. They must stay identical to EN.
- Place names come from the database (`places.name_en/ne/hi`), never from messages. Timeline text uses `what_en/ne/hi`.
  Stat captions use `caption_en/ne/hi`.

## 3. Numbers, dates, cadence

- Numbers: `fmtInt` → Latin digits with thousands separators in all languages.
- Dates: `fmtDay` / `fmtTime` / `fmtDayTime` / `fmtAsOf` in `Asia/Kathmandu`; month abbreviations are localised
  (`lib/format.ts` → `MONTHS`), digits stay Latin.
- Cadence copy: `fmtCadence(lang)` renders `PULL_INTERVAL_MINUTES` as "4 hours" / "4 घण्टा" / "4 घंटे" so the
  interval is never hard-coded in a translation.

## 4. Adding a language (numbered)

1. Add the code to `LANGS`, `LANG_LABELS`, `LANG_NAMES`, `LANG_TAGS` in `lib/i18n.ts` and `SPEECH_LANG` in `lib/config.ts`.
2. Copy `messages/en.json` to `messages/<code>.json` and translate every value; keep placeholders and Latin-only keys.
3. Add month abbreviations to `MONTHS` in `lib/format.ts`.
4. Add the code to the `proxy.ts` `LANGS` array and to the `stripLang`/`LangToggle` regexes.
5. If the script needs a larger line-height, extend the `html:lang()` rule in `app/globals.css`; add the font subset
   in `app/[lang]/layout.tsx` if Baloo 2 has it.
6. `npm run i18n:check && npm test && npm run build`.

## 5. Adding a string (numbered)

1. Add the key to `en.json` (namespace by page/block: `sec.*`, `report.*`, `me.*`, `place.*`, `sources.*`, `about.*`).
2. Add the same key to `ne.json` and `hi.json` in the same position.
3. Use `t(lang, "key")` in the component; never inline English.
4. `npm run i18n:check`.

# 10 · The 3D corridor (section 01)

`design/Design form preferences/corridor-3d.js` (three.js r160, procedural low-poly terrain) ported as-is to a
TypeScript module and fed with live place data.

```
  v_place_status_latest ⋈ places ──lib/corridor.ts toCorridorPlaces()──▶ CorridorPlace[] { id, name, km, side, off, reported, confirmed, unknown, last, heavy }
                                                                             │ (plain data crosses the server → client boundary)
  components/blocks/Corridor.tsx (server)   section head · legend · <Frame> · caption · mobile compact list
        └─ components/blocks/CorridorIsland.tsx ("use client", next/dynamic ssr:false)
              └─ components/three/CorridorScene.tsx   connection check → lazy import → mountCorridor() | fallback <img>
                    └─ components/three/corridor-3d.ts  the ported scene: terrain · flood tube · lakes · markers · lights · camera · orbit · pick
```

## 1. The port (`components/three/corridor-3d.ts`)

Identical maths and parameters to the design script: `kmToX`, `meander`, `baseElev`, `n2`, `terrainH`,
`PlaneGeometry(96, 52, 150, 80)`, flood `TubeGeometry` along km −10…74, two barrier lakes at km −8/−6, cylinder +
sphere markers with `h = 1.5 + √reported × 0.32`, colour `0xb06a00` (unknown / reported > 0.4) or `0x1c7a45`,
lights, `PerspectiveCamera(42)`, `az −0.9 · pol 0.98 · rad 62`, drift, pointer orbit, wheel zoom (28…120), raycast pick.
Differences: `import * as THREE from "three"` (npm, no CDN); markers come from `opts.places`; the pick calls back
`onPick(place, x, y)` instead of writing innerHTML; `dispose()` cancels the loop, disconnects the ResizeObserver,
removes listeners and frees geometries/materials/renderer; a missing WebGL context throws so the caller can fall back.

## 2. Data shaping (`lib/corridor.ts`)

- `km` = `place_status.km` else `places.km`; places without km are not in the scene (they stay in the tables).
- `side` is a deterministic hash of the id: ±0.3…0.7 on the channel; ±3…7 (and `off = true`) when `places.in_channel = false`
  (Langtang-style side valleys). Scene z = `meander(x) + side × (off ? 1 : 2.2)` — exactly the design's formula.
- `heavy` = `unknown / max(1, reported) > 0.4` → amber marker; `last` is preformatted `fmtDayTime`.
- `statusTone` (also used by the compact list and the place page pill).

## 3. Client behaviour (`CorridorScene.tsx`)

1. Mount → if `navigator.connection.saveData` or `effectiveType ∈ {slow-2g, 2g, 3g}` → fallback image.
2. Otherwise after first paint (`requestIdleCallback` / `setTimeout`) → `import("./corridor-3d")` (three is code-split)
   → `mountCorridor`. Any error → fallback.
3. Pick → React card (name · reported · confirmed · unknown · last contact · "Place page →" Link); click on terrain closes it.
4. A visually hidden list of place links keeps the section usable by keyboard and screen readers.
5. Unmount → `dispose()`.

## 4. Fallback PNG

`public/corridor-fallback.png` (1280×480, < 60 KB) is generated by `npm run fallback` (`scripts/make-fallback.mjs`):
an SVG drawn with the same meander/terrain maths projected obliquely — terrain facets, red flood path, two lakes,
sample markers — rasterised with `sharp` to a 48-colour palette PNG. No text inside the image; legend and caption
are HTML outside the frame. Regenerate whenever the scene's geometry changes.

## 5. Legend, caption, mobile

Legend dots (mostly unknown `#ffae42`, mostly reached `#148a4e`, flood path `#ec3013`) and the caption "Marker size =
people believed there · tap a marker for the place card · drag to orbit" are rendered by `Corridor.tsx`. On mobile the
panel is 400px tall and a compact list (dot · name · unknown) of the eight highest-unknown places sits under it.
